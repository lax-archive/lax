# Hardening audit of 0.1.31 → 0.1.35 (2026-09-03)

Closed record of the audit that read everything `lax` shipped between
release 0.1.31 (`ce92b71`) and 0.1.35 — the paper layer, the ReflowTeX web
view, loginless ids, supersedes chains, four source hosts, declared-input
restriction, outcome classification, the new validators, and the proof-tree
generator — probed it by execution, and attacked it. The rendered report is
the artifact <https://claude.ai/code/artifact/2fef5e08-c4eb-48e4-ad04-ac5a0306e732>;
this file is its text, kept where the lessons live. Open follow-ups moved to
TODO.md; the fixes are in git.

**Scope.** 57 commits, 10,726 lines of `src`, 121k lines total, 15 audit
dimensions, 73 agents. 51 findings raised → 40 survived verification, 29 of
them reproduced by execution.

**Verdict.** Sound enough to keep running. Nothing that survived
verification writes a wrong record, crosses a trust rule, admits an invalid
submission, or leaks a credential. Every defect found fails closed. But
three things should land before the next release or the next paper round
trip — and one of them had already cost a publication once, on lax-65, on
the day it was introduced.

**Board at the time of the audit.** CI on `main` red since `87b0f54`
(13:06), two releases shipped over it. Unit + e2e: 663 pass, 12 skipped
(TeX/fork gates, satisfied in CI). Container smoke 8/8 — the first
successful run since 13:06, once the crash was fixed. `lax-database`: 36
records consistent, 33 dependency edges, 3 supersedes edges, no dangling
refs, no digest mismatch. Verified defects: 40 — 0 critical, 2 high, 16
medium, 22 low.

## Fix now — 3

Ordered by consequence.

**01. CI is red, and two releases shipped over it.** *(production)*
`test/smoke/submission-validation.ts` crashed at module load — the driver
calls `fixtures()` while `SMOKE_PDF` is still in its temporal dead zone —
so the container smoke, the only real-container coverage, died in *the very
commit that changed the picture conversion the smoke exists to check*.
0.1.34 and 0.1.35 both shipped without it ever running.
*Fix:* the fixture blobs are hoisted above the driver (all 8 fixtures pass,
including `paper-web` with its MuPDF and virtual-font assertions); then make
the class unshippable — wire `smoke:prooftree` into `ci.yml` (it runs in no
job today) and add a `tsc --noEmit` over `test/**` and `scripts/**`, which
nothing typechecks because `tsconfig.json` includes only `src/**`.
`test/smoke/submission-validation.ts`, `.github/workflows/ci.yml`,
`tsconfig.json`

**02. A successful validation is refused at publish by its own warning
text.** *(reproduced, 3 lanes)*
`FindingCollector.warn` pushes messages verbatim; the trusted publisher's
`parseFinding` rejects anything that is not one line, NFC,
control-character-free and under 8000 bytes. So a validation that succeeds —
Lean chain green, paper compiled, web view merely skipped as designed —
writes a report the publisher then refuses, and the author gets
*"Publication failed … validation warning 1 message must be one line"*,
identically on every retry, pointing at nothing.

The trigger is not exotic. `extract.ts:61` builds its error with a literal
newline, and `web.ts:569` catches it into a `web-oracle` warning on an
`ok:true` report — so any timeout or nonzero exit of the heavier `--text`
pass loses the publication deterministically. An NFD figure name
(`café.png` as macOS stores it) does the same through
`web-pictures-dropped`. This is the class that cost the lax-65 round trip:
`009c9d5` sanitized the three transcript tails that caused it and introduced
a fourth unsanitized interpolation in the same commit.
*Fix:* move the rule to the boundary. Generalize `oneLineTail` into a
`oneLineMessage` and apply it inside `FindingCollector.warn`/`violate`, not
at call sites — the call-site approach has now been missed five times. Then
have `writeValidationOutputs` run its own successful report through
`parseSuccessfulValidationArtifacts`, so a report the publisher will refuse
can never leave the validate job, where the artifact could still explain
itself.
`src/submission-validation/findings.ts:9`, `artifact-schema.ts:655`,
`paper/extract.ts:61`, `paper/web.ts:569`, `outputs.ts:120`

**03. Delete under-reports its dependents, and the test asserts the bug.**
*(reproduced, live data)*
`listDependents` searches `requiredByProofs` only for `LaxNProofs`, but a
proofs package requiring another submission's *concepts* package records the
bare `LaxN` — the commonest edge there is. Against the live database:
`/lax delete lax-18` reports "No known live dependents" while lax-54
requires `Lax18`; deleting lax-14 would miss both lax-12 and lax-5. Deletion
is permanent and retires the id, and `resolution.ts` then refuses the
stranded dependents forever.

Separately, the same function returns a *lexicographic* sort where the
trusted publisher demands numeric order — so a delete whose dependents span
`lax-5` and `lax-12` dies in `parsePublishRequest` outside the try, posting
the generic operational-failure comment and never succeeding on retry. Its
sibling five lines below, `listRegisteredSuperseders`, already uses the right
comparator.
*Fix:* `[...concepts, ...proofs].some(n => submissionIdForPackage(n) === id)`,
as `archive-preflight.ts:71` and `publisher.ts:598` already do, plus the
numeric comparator. Then add the `requiredByProofs: ["Lax13"]` case and a
numeric-order pair to `test/unit/archive-dependents.test.ts`, whose expected
value currently encodes both bugs.
`src/shared/archive.ts:147`, `src/shared/archive.ts:149`,
`src/shared/publisher.ts:583`, `test/unit/archive-dependents.test.ts:36`

## Fix soon — 11

Each is a small, local change. None of them corrupts anything.

- **Paper-side infrastructure faults are reported as author content
  violations.** `paper/phase.ts:73` never calls `containerBoundaryFailure`,
  and `pipeline.ts:429` flattens every thrown `PipelineFailure` into a
  `paper/runtime` violation. A failed TeX-image pull — a multi-gigabyte
  image, fetched fresh on every paper-bearing run with no retry — tells the
  author their paper did not compile. A `PAPER_IMAGE` pin whose PATH lacks
  latexmk would reject *every* paper submission "on content" with exit 127.
- **`lax rekey` skips `.tex`.** Three lanes found this independently.
  Packages, imports, namespaces and the manifest are renumbered; every
  `% lax begin Lax0.Foo` marker is not, and the next build rejects them with
  a message blaming the lakefile requires. `rewrite.ts:196` documents a
  renumbering contract that rekey does not honour. Add `.tex`/`.bib` to
  `TEXT_EXTENSIONS`; `assets/instructions.md:91` also still describes the
  retired `lax-0` flow.
- **Symlink escape from the paper sandbox.** The five post-compile
  `writeFileSync` calls at `web-container.ts:881` are the only writes in that
  module without an `lstat` — and the comment above them asserts the
  opposite. A symlink planted by the untrusted `-shell-escape` compile
  redirects a trusted host write anywhere on the runner. Bounded (the runner
  is ephemeral and credential-free, and both cache saves precede untrusted
  execution), but it is a stated invariant that is false. `rmSync({force:true})`
  before each write.
- **Local build fails on untracked junk inside the packages.**
  `package-files.ts:14` walks the filesystem while the trusted path sees only
  a checkout, so a `.DS_Store` or an editor `.swp` inside `concepts/` blocks
  `lax submit` for a commit the archive would accept — and gitignoring it, the
  natural fix, does nothing. Intersect with `git ls-files` on the local path.
- **BibTeX rejects valid entries.** `bibtex.ts:55` toggles quote state at
  brace depth 1, where a `"` is an ordinary character to both bibtex and
  biber, so an entry with an odd number of straight quotes inside a braced
  value is refused. Pass `trackQuotes=false` from `validAtom`.
- **The fidelity oracle can be talked into a pass.** `web.ts:594` subtracts
  unreferenced captures from the PDF side with no bound on length, count or
  fraction — 7 of 8 paragraphs subtracted turns a 0.9524 skip into a sealed
  bundle carrying one paragraph. Cap the subtracted fraction.
- **…and into a false rejection.** `web-oracle.ts:58` collapses whitespace
  before matching folios, so any line whose non-space characters are up to
  four digits is deleted from the PDF side. Verified on a real PDF: 4 of 8
  small-integer table rows dropped, similarity 0.9711 against the 0.98 floor.
  Require a single whitespace-free token.
- **Proof-tree witness selection can build a cycle.** `prooftree.ts:136`
  picks each statement's grounded witness with no acyclicity constraint, so a
  statement with a competing proof is reported as an unresolved leaf in about
  half of runs — a headline result decided by `randomInt`. Unreachable with
  today's 36 records (no statement has two proofs). Restrict eligibility to
  lower-rank proofs.
- **Pre-paper-layer folders go dirty after a build.** `build.ts:294` writes
  `paper.pdf` into roots whose `.gitignore` predates it, and `lax submit`
  then refuses the worktree, naming nothing the author edited. Append the
  ignore lines on first write; add the names to doctor's generated-file
  check.
- **A CRLF issue body stops routing.** `issue-reservation.ts:23` anchors on
  the first line, and the GitHub web UI stores bodies with CRLF — so editing
  a control issue in a browser breaks that submission's control plane until
  the body is restored. Normalize `\r\n?`, as the comment formatter already
  does.
- **`paper-web.tar` is missing from both generated-file guards.**
  `static.ts:161` and `:228` enumerate exactly the files a build writes, and
  the paper layer added a third. One word each. Latent until the host deriver
  gets a CLI surface.

## Record and move on — 6

- **Supersedes ownership is checked by two different predicates** — four
  findings, one fact. The necessary/sufficient split is documented in
  spec-notes and fails closed (the publisher is strictly stricter, so nothing
  invalid can be published). What survives is that `lax register`'s preflight
  prints the permanence note and demands a typed confirmation for a
  supersession the archive will refuse, and that `instructions.md` and a
  docstring at `resolution.ts:251` state only the weaker rule.
- **The count-check diagnosis names the wrong cause** when a marked `.tex` is
  simply never compiled — it offers verbatim, moving argument and display
  math, but not "that file is not part of your main document".
- **The oracle prints a bound as if it were a measurement** — when Myers'
  search exceeds its budget it reports `floor − 2/total`, so a true
  similarity of 0.0 is shown to the author as 0.9799, a hairline miss.
- **Duplicate `\input` collapses destinations silently** — pdfTeX warns and
  latexmk does not fail; one card shows the first inclusion. Scan the
  transcript for "duplicate ignored".
- **Proof-tree housekeeping** — a failed re-run leaves a stale `.olean`
  beside no report; concurrent capture promotion crashes with `ENOTEMPTY`;
  the runtime cache key omits the toolchain that `warmDir()` includes.
- **Two stale comments** — `submit-publisher.ts:256` claims
  `parseArchiveFiles` re-validates a published `paper` block, which it does
  not; the `web-container.ts` symlink comment (above) says the writes are
  guarded.
- **A cancelled validate job leaves no comment and a stuck progress
  reaction.** The adjudicator wanted to drop this as unreachable; it is not.
  7 of the last 200 control-plane runs were cancelled, so an author has
  almost certainly seen an issue that simply stopped answering.

## The pattern

The weeks were not careless in the sense of sloppy code. Every module is
internally careful; most defects needed contrived input to break. They were
careless in one specific, fixable way: **rules were copied to call sites
instead of placed at boundaries, and the new features added copies that
disagree with the originals.**

One rule, many copies — and the paper layer updated some of them:

| The rule | Where it lives |
| --- | --- |
| The set of lax-owned file names | 5 places — scaffold `.gitignore`, `static.ts:161`, `static.ts:228`, build removals, doctor |
| Dependent matching | 3 places — one differs, and it is the one delete uses |
| Supersedes ownership | 3 code paths + 2 documents |
| One-line message sanitization | 4 call sites, missed at a fifth — never the collector |
| Container-boundary classification | every Lean phase, **not** the paper phase |
| `lstat` before touching a compile output | everywhere in `web-container.ts` except 5 writes |
| Rekey's extension list | vs. the file types the tree now actually holds |

Every medium finding is one of two shapes: *a new feature added a fresh copy
of an existing rule*, or *an existing enumerated list was not extended for
the new feature*. The paper layer in particular was built as a sibling of the
Lean phases — same shape, its own seams — rather than through them.

Two habits kept the class invisible. Tests were written from the code rather
than from the contract: `archive-dependents.test.ts` asserts the bug, the
loginless-init tests rekey a scaffold that has no paper, no test pushes a
real warning through the publisher's real parser, and the only real-container
coverage was not even loadable. 119k lines of test, and the three worst
findings sit on seams no test crosses — validate report → publisher schema,
local build → trusted verdict, resolution → publisher. And incidents were
fixed at the site rather than at the class, on the day they happened:
`009c9d5` sanitized the three tails that broke lax-65 and added a fourth
unsanitized interpolation in the same commit; `a215ea4` turned an
always-empty `listDependents` into a half-right one and wrote the test to
match.

The remedy is structural and cheap: one sanitizer in `FindingCollector`, one
shared package-match used by all three callers, one `LAX_GENERATED_FILES`
constant, `containerBoundaryFailure` in every container-running path — and
then one test per seam that drives the producer's real output into the
consumer's real parser.

## What was not proven

So it is clear what is trusted rather than known.

- All of this is module-level probing. No fix was rehearsed end-to-end on a
  scratch repo, and the "valid submission rejected on content" end state was
  reasoned from the pipeline, not executed with a green Lean chain behind it.
- The Lean side — Compile, Replay, Inspect, captures, sandbox mounts — was
  barely in the window and was not re-attacked. The paper container's posture
  beyond symlink writes (network reachability under `-shell-escape`, the env
  allowlist) was examined by nobody.
- The four new Git source hosts produced no finding, and were probed against
  the fake, not against real GitLab, Codeberg or Bitbucket remotes.
- The proof-tree composer's Lean side was reasoned about for axiom honesty,
  not run. Its selection defect is unreachable only because no statement in
  today's archive has two proofs.
- The database audit is consistency, not re-validation: no capture was
  rebuilt.
- Nine low findings were read by no verifier. They look real; they are
  unreproduced.

## Method

Five parallel lanes over 15 dimensions — ids and init, control plane and
trust rules, supersedes, source fetch and declared inputs, validators,
outcome classification, paper markers, paper sandbox, paper web fidelity,
prooftree, the CLI journey, test quality, plus four cross-subsystem seams.
Each auditor read the diff and the code and then probed it by executing the
real modules with `tsx`; every non-trivial finding was then attacked by one
or two skeptics whose default verdict was *refuted* and who had to reproduce
it or find the guard that makes it unreachable. Severities were revised down
far more often than up. A final adjudication pass reviewed all 40 survivors.

Also run: the full suite twice (663 pass, 12 skipped), the container smoke
over all 8 fixtures, the proof-tree smoke, a consistency audit of the live
database clone, and live checks of laxarchive.org's lax-65 paper page.
