# Review: the axiom-free program charter, under the "suggestion became a constraint" light

Legend: **[V]** verified in repo/toolchain/database/spike logs; **[R]** reasoning.

## Verdict

The idea Jan wrote down in 24 lines (`axiomfree.md`) is sound and the spike proves the tool does what he wants (`spike/axiomfree/REPORT.md:13-33` [V]). The 574-line charter that grew around it is not a plan for that idea; it is a plan for everything an outside reviewer could imagine going wrong, with each imagined failure promoted to a contract. Of its nine Decisions, three are reviewer suggestions hardened into rules the same afternoon (D7, D8, D9), one is an agent process preference (D5), and one Jan did choose but whose cost was never put against the zero-cost alternative (D6). Two contracts (C1 visibility, C6 captures) exist only because the spike happened to write `module` files, which the spike itself reports are optional (`REPORT.md:246` [V]). The universe decision would reject 103 of the 635 registered statements in the live database, including 27 in the flagship Lax17 and 24 in lax-68 [V]. The planned `lake check` step is the one thing the spike found to be a memory wall. And the "concept gate must fall before W2" prerequisite is only a prerequisite because of the one workstream (W5, whole-environment certification) that the reviewer recommended deferring and the charter refused to defer. The smallest system that delivers Jan's four goals is roughly: a new environment row, one new inspector field, one validator rule change, one generator of ~150 lines, one extra container step, and a bundle in the existing capture store. That is one session's work plus a rehearsal, not eleven workstreams on an integration branch.

## 2. The simplest thing that works

Goal restated: claims rest on the kernel; no axioms; conditional proofs compose; a rerunnable certificate.

1. **Environment row** `v4.35.0` with `specVersion: 2` (`environments.ts:28-46` [V] already has the shape; admission is a table row plus a tag, as on 2026-09-04). Files keep the spec-1 style: no `module` header, ordinary `import`. Nothing about visibility, exposure, or capture sidecars changes.
2. **Concept rule (validator, spec-2 rows):** a statement is a definition-kind declaration of a concept module whose stored type is raw `Sort 0`, with no binders; the `axiom` kind is a violation (`inspect.ts` already reports `kind` [V], `Main.lean:136-137`); the allowed axiom set is background-only — that is *deleting* the "statements of required packages" branch from the existing walk (`inspect.ts:106-152` [V]), not adding one. Marker: either structural (every closed public `Prop` def in a concept module is a statement) or Jan's attribute — see 4a.
3. **Proof rule:** inspector adds one field, `telescope` (ordered `const` names with level args and binder info, or null); validator: theorem kind + telescope non-null + every const a statement of a required package → proof with edge `{S₁..Sₖ} → C`. ~40 lines of Lean in `Main.lean` (the type walk is a `forallE` loop; no kernel work), ~60 lines in `inspect.ts`. `build-output.json` proof entries gain `telescope`; `conclusion`/`assumptions` derived from it, so lax-website and `selectProofTree` (`src/cli/prooftree.ts:92` [V]) keep working.
4. **Per-submit certify step** (after Compile, Replay, Inspect): lax generates `Challenge.lean`/`Solution.lean`/`comparator.json` from the telescopes (escaped names, `@proof.{…} h₁…hₖ`); container A (concept captures + mathlib mounted ro, no proof package) builds and exports the Challenge; container B gets `challenge.export` **read-only**, the proof capture, and runs `lake comparator --challenge-from-export … --inadvisably-no-sandbox` (flags exist, `Lake/CLI/Main.lean:84-88,420-426` [V]; 10.5 s on the toy, `REPORT.md:85` [V]). Exit 1 → violation. Replay stays (4e).
5. **Rerunnable certificate:** the generated bundle (four small files, no exports) is pushed to the existing digest-addressed capture store (`src/shared/capture-store.ts` [V]) and its digest recorded in `build-output.json`, exactly as captures are. `lax certify <id>` fetches it and runs `lake comparator` (with `--paranoid` if the user likes). Relative/implied-edge certificates compose Solution bodies along `selectProofTree`'s forest — the only genuinely new algorithm, and a CLI-side one.
6. **Spec draft, `lax init` scaffold, instructions section, port of the two flagship drafts** (`src/cli/port.ts` exists, 410 lines [V]).

What the charter adds that the goal does not require, and the cost of adding later:
- **W5 scheduled whole-environment run + C5 verdict format + 9.4** — records and environments are immutable and the judge is frozen (D4), so a scheduled rerun of per-submit verdicts yields no new information; it only yields one downloadable bundle. Later cost: a script that concatenates per-record bundles into one Challenge/Solution pair, when someone asks for it. Jan's "on a regular basis" is satisfied by "every submit".
- **W6 badges from C5** — later, once there is a verdict to show; v1 marks "certified (bundle digest …)" from build-output.json.
- **W10 LaxCore** — see 4a; adding a marker later is a spec minor and a one-line rewrite in every spec-2 file; the port tool can do it.
- **D7, the universe rule** — see 4b; a *stricter* rule later is painful, a *looser* one is free. Start loose and structural.
- **The classification matrix, the helper hint, the random prefix, the expected-result adversarial suite, the advisory/suspension machinery, `lax doctor` kernel reporting** — all can be added when an incident or a port asks for them; none changes a data shape.
- **The integration branch, per-workstream plan files, the governance section** — zero later cost; see 3.

## 3. Scope and process inflation

The environments plan (`history/environments-plan.md:418-448` [V]) was six stages, stage 0 "half a day", all landed in one day with one rehearsal, one admission run, and one history note. The audit (`history/audit-20260903.md:216-258` [V]) found that this codebase's real failure mode is *rules copied to call sites instead of placed at boundaries*. The charter's shape invites exactly that: eleven workstreams "in parallel in separate sessions or worktrees" (`:8-9`), each writing its own plan file, branching on `specVersion` at eleven named places (`:243-247`), merged behind `npm run check` on a branch that reaches `main` only "as part of W8 … in one release" (`:473-476`). One maintainer cannot review eleven parallel worktrees; the parallelism serves the agents, not the work. The integration branch guarantees a big-bang merge of the kind the audit warned against, and contradicts the project's own practice (every environments stage shipped to `main` as a release). The governance section (`:556-574`) — charter amended only by decision, deviations logged in status headers, measurements never in TODO — is ceremony for a one-person project whose TODO.md is explicitly "the canonical list of next steps".

Serving the work: the contracts' *content* on telescopes and `lake-manifest.json`; the risk register row on replay cost; the rehearsal gate (`scripts/rehearsal/`, the standing rule). Ceremony: the branch, the plan files, the verdict format, the governance section, the dependency diagram, "Jan may veto" items recorded as fixed decisions.

## 4. Sanity checks

**(a) LaxCore.** An attribute does require an imported library — `registerTagAttribute` runs in `initialize`, and the attribute can only be applied in modules that import its declaring module (`Lean/Attributes.lean:180-215` [V]). So if the marker is an attribute, a library exists. But: (i) *one commit works for every environment* — the module is `import Lean` only, and lake does not enforce a dependency's `lean-toolchain`; per-environment tags and per-environment `lean-toolchain` files (`:363-371`) are invented work. (ii) The library must be pre-materialised in the networkless warm store like mathlib (`host/setup.ts` [V]) — real provisioning work and a new entry in the trust base, as the charter admits (`:76-78`). (iii) The alternative the charter does not weigh: statement-hood **structural**, exactly as it makes proof-hood structural in D3 and declines a proof marker in 9.8. "A closed public `Prop`-valued definition in a concept module is a statement" costs nothing, needs no repo, and the asymmetry (proofs structural, statements marked) is unexplained. Closed `Prop` auxiliaries that are *not* claims are rare — parameterised predicates are not closed. If Jan wants explicit intent, the cheapest honest marker is the spec-1 idiom he already has: the concept docstring, which the inspector already parses (`Main.lean:62`) — rejected "for not being Lean idiom", but `axiom` was the idiom in spec 1 and that is being removed anyway. Recommendation: structural for v1; attribute as a spec-2.1 minor if real ports show auxiliaries being mistaken for statements. [R on the recommendation; V on the mechanics.]

**(b) Universes.** Live database (`~/.lax/lax-database`, 104 records, 808 statements, 805 proofs [V]): **115 statements are universe-polymorphic** (`Type u` 75, `Type u_1` 36, `Type v` 4), 103 of them in registered records across 14 records — Lax17 has 27, lax-68 has 24, lax-146103 (automata), lax-10, lax-18, lax-54, lax-57, lax-871432 [V]. D7 would force every one to be rewritten to `Type`. The reviewer's hypothetical ("if real submissions need them") is the live corpus. The comparator itself compares universe params as part of `ConstantVal` (`REPORT.md:181-182` [V]), so it is not the obstacle; the name-only graph is. The fix is one structural rule, not a prohibition: a proof's conclusion and hypotheses must instantiate each statement constant with distinct level *variables* of the proof (never a concrete level), so every edge is universally quantified over universes and name-only composition is sound; the generated Challenge theorem copies the proof's level params. That is a check over the `telescope` C3 already records. [R]

**(c) Hygiene walk vs `lake check`.** The walk is not double work — it is existing code with a smaller allowed set. The double work is **`lake check`**: W4 plans it on every concept package (`:405-406`), yet the spike shows it exports the whole closure (162k decls, 714 MB), takes 285 s, and kills `nanoda` at 17 GB (`REPORT.md:87-90` [V]); and A4 shows it *cannot* catch the unused `axiom` it was kept for (`Lake/Check/Axioms.lean:60`, `unless ref == name` [V]). Replay (`phases/replay.ts` [V], `leanchecker` over the oleans, 3.3 GiB measured peak at the epoch, `history/environments-roundtrip-20260904.md` [V]) already re-kernel-checks every declaration of both packages. **Drop `lake check` entirely**; keep Replay + the walk with background-only allowed set + the kind refusal.

**(d) Concept gate.** The trusted-imports threat is: a concept package that runs code at elaboration alters what a *generated* Challenge means. With **per-record** Challenges, the imports are exactly the concept packages the proof author chose to depend on — whose statements' *meaning* that author already trusts today (faithfulness is "the social layer", charter non-goal `:46-47`). The blast radius becomes global only with a **whole-environment** Challenge that imports every concept package (W5). Drop W5 for v1 and 9.7 is no longer a prerequisite; the website states "concept authors you depend on are trusted, as today". The dialect (`spec_conceptdialect.md`, 577 lines, zero implementation, forbids `module` forms per codex A2 [V]) stays its own project. [R]

**(e) Comparator vs Replay.** The comparator replays only the named theorems' cones (`REPORT.md:195-200` [V]). Replay authenticates *every* declaration of both packages, which is what makes the inspector's axiom sets "kernel-grade" (`spec.md:1017-1029` [V]). W4 says the comparator is "replacing Replay — the hygiene walk stays" (`:405-407`): with Replay gone, the walk degrades to metadata-grade over Compile-written oleans, and non-cone declarations of the *proof* package are never kernel-checked (`lake check` was only planned for concepts). **Replay stays; the comparator is added, not substituted.** Cost: Replay is already paid today.

**(f) Per-submit and scheduled.** Per-submit is enough for v1 (see 2 and 4d). The reviewer recommended deferring W5 (`codex-review:386-390` [V]); the charter declined (`:570-571`). The spike measured neither the union-of-cones nor the per-package-closure variant (`REPORT.md:129-131` [V]), and the closure variant hits the memory wall.

**(g) Contradictions with trust rules and existing design.**
- D9/9.1 "VM with bubblewrap" moves untrusted execution (the Solution build elaborates the proof package: initializers, macros) *out of docker onto the runner VM*, contrary to CLAUDE.md "untrusted code runs in docker containers … allowlist-only mounts", and it depends on an AppArmor profile no package ships, unmeasured on GitHub runners (`REPORT.md:150-157,267-270` [V]). The reviewer's C4 objection ("a build can overwrite the Challenge export before comparison") is answered by lax's existing mechanism — read-only mounts: build and export the Challenge in a container without the proof package, then mount `challenge.export` read-only into the Solution container and run `--challenge-from-export … --inadvisably-no-sandbox`. The Solution build cannot touch the Challenge, the toolchain is already mounted read-only, and a forged *solution* export must still pass the kernel against the read-only Challenge. If Jan wants belt and braces, a third clean container compares both `--*-from-export` files with nothing untrusted in it — and that from-export path is how a rerun of a published bundle works anyway. **Yes, no-sandbox inside the existing docker sandbox is the pragmatic first version**, with the Challenge exported separately; the custom Dockerfile/unconfined-seccomp route (`REPORT.md:166-175`) should be rejected outright.
- W4's "replacing Replay" (see e) contradicts `spec.md:1014-1023`'s trust chain.
- C6 capture sidecars contradict nothing but are avoidable (no `module` headers).
- The charter does not state where per-submit bundles live; the obvious home is the capture store, trust rule 2's "digest before the database commit" pattern, which no workstream mentions.

**(h) What `REPORT.md` makes unnecessary or wrong as written.**
- **W4's `lake check` on concepts** — wrong (memory wall, `:87-90`; and A4). Drop.
- **D9 and 9.1's two options** — the VM option rests on an unshipped profile (`:150-157`); the docker-with-bwrap option needs seccomp/apparmor/systempaths unconfined plus a custom image (`:166-175`, "reported, not recommended"). The option that needs none of this — read-only Challenge export + no-sandbox — is the one the charter forbids. Rewrite D9 as "the Solution build never has write access to the Challenge export or the toolchain", which docker already gives.
- **C1 visibility rules, C3 `visibility` field, C6 capture sidecars, W7's `@[expose] public def` scaffold, W0 "blocker (2)"** — unnecessary if spec 2 keeps header-less files (`:104,246-248`).
- **9.2 `--paranoid` per submit** — the full set is 5–9 ms/decl and `nanoda` is "the memory hog" (`:112-117,90`); on a 30k-decl cone that is ~5 min, on a Lax17-sized cone unknown. Per submit: the comparator's default (Lean kernel); `--paranoid` in `lax certify --run` and on any later batch job; the badge says "Lean kernel; rerun with `--paranoid` yourself". The report shows `lean4lean`/`con-leche`/`con-ron` were never run on anything large (`:273-275`).
- **W0's expected-result/adversarial suite rewrite** — the three negatives that matter reached the comparator (`:92-96`); the shadow objection is closed. A regression suite belongs in `test/` with the generator, not in the spike.
- **C4's randomised module prefix** — shadowing is caught on content (`:95`); keep fixed names.
- **W5/C5 cost model** — the only measured whole-closure path is the one that OOMs; the report explicitly did not measure the union-of-cones path (`:129-131`). W5 cannot be planned from these numbers; another reason to defer it.
- **D7** — the report's own finding that the comparator compares universe params whole (`:181-182`) means polymorphic statements are fine for the judge; the restriction is lax-internal and the corpus says no.
- Still true and necessary from the report: `lake-manifest.json` in the bundle, exit codes 0/1/2, "compile error is also exit 1" (the pipeline must distinguish by phase), the unfolded-conclusion rejection (statements must be named constants, not defeq), per-submit cost ~10 s.

## 5. What a pragmatic senior engineer would do

Drop the integration branch, because every earlier program in this repo shipped stage by stage to `main` behind the rehearsal and that is how one maintainer stays in control. Drop W5, C5, 9.4, and the advisory/suspension machinery, because immutable records plus a frozen judge make a scheduled rerun information-free, and dropping it also removes 9.7 as a blocker. Drop `lake check`, because the spike measured it as the only memory wall and it cannot do the one job it was kept for. Drop D7, because 103 registered statements say otherwise; replace with the level-variable rule. Drop the `module` header and everything downstream of it (C1 visibility, C6 sidecars), because the spike says it is optional and the dialect forbids it. Drop D9's VM, because the project's sandbox is docker and read-only mounts already answer the threat. Defer LaxCore, because structural statement-hood is symmetric with structural proof-hood and costs no repo. Defer the classification matrix, the helper hint, the random prefix, the port rewriter — add each when a port needs it. Keep: D1–D3, telescopes in the inspector and `build-output.json`, the per-submit comparator in a container, the bundle in the capture store, `lax certify`, Replay, the walk, the rehearsal gate.

**The single first deliverable:** one local `lax build` in a fake-mathlib spec-2 environment that, for a two-record chain with one conditional proof (A→C with A proven elsewhere), produces a `telescope`, generates the bundle, runs the comparator in the existing docker runner with the Challenge export read-only, and fails the build on each of the three negatives. That exercises the inspector change, the generator, the composition rule, the sandbox layout, and the capture/bundle format, and it is the thing nobody has built yet. Everything else in the charter is either already known to work (the comparator) or is not needed until that works.
